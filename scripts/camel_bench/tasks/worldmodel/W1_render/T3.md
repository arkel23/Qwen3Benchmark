This repository is missing `pong/render.py`. Write that file so the rest of the engine works as the
repository documents, and so a rendered frame determines the visible state it came from.

Read `README.md`, `pong/sim.py`, `pong/rules.py` and `pong/data.py` first: they define the visible
state and how the renderer is called.

The file must provide:

- `tiles(cell)`: the tile bitmaps as a `uint8` array `(4, cell, cell, 3)`, one per cell kind in the
  order background, paddle, ball, score pip. Each kind is a distinguishable shape drawn in its own
  colour on the background colour.
- `frames(visible, heights, cell)`: visible states `(N, T, 4)` of `(paddle top, ball x, ball y,
  misses)` and paddle heights `(N,)` to `uint8` RGB frames `(N, T, 16 * cell, 16 * cell, 3)`.

The playfield is the 16x16 integer lattice. Column 0 holds the paddle, occupying rows `top` to
`top + height - 1`. The ball occupies the cell at row `y`, column `x`. Row 0 carries the miss count
in binary, one pip per bit, so that different miss counts give different frames. Rendering must be
injective on `(height, top, x, y, misses)`: two different visible states never produce the same
frame.

Follow the repository's own conventions. Create the file and stop; do not change anything else.
